# Theme maintenance map

`themes/PresenceMessages.theme.css` and `themes/PresenceSnapchat.theme.css` are standalone Vencord themes. Both are copied into the release DMG for users to install separately and select one at a time. The presence plugin must not select them, mutate the user's theme settings, or bundle their selectors into `suite.css`. Keep the themes local: no `@import`, network URLs, remote fonts, or scripts.

Snapchat is generated with `npm run build:themes` from the verified Messages surface map plus `themes/snapchat.variant.css`. The generator gives it a separate `--ep-snapchat-*` namespace and includes all CSS in one download; it does not import Messages at runtime. Edit the variant for Snapchat geometry/palette and regenerate after a Messages compatibility fix. A freshness test catches forgotten regeneration. The Snapchat treatment is an adaptation: sender-color rails, inset quote cards, wrapping reaction chips and restrained yellow navigation accents; it adds no read/opened or disappearing-message claims.

## Tokens

Theme-owned palette and material tokens live under `--ep-messages-*`:

- `--ep-messages-chat`, `--ep-messages-sidebar`, `--ep-messages-floating`, `--ep-messages-glass`, `--ep-messages-backdrop`
- `--ep-messages-text`, `--ep-messages-muted`, `--ep-messages-incoming`, `--ep-messages-blue`, `--ep-messages-blue-high-contrast`, `--ep-messages-border`
- `--ep-messages-wallpaper-veil` for the opt-in DM photo/preset layer

Discord's `--chat-background-default`, `--background-base-*`, `--background-surface-*`, and `--background-mod-*` aliases map to these surfaces. Chat and sidebar use denser tints to stay readable over bright desktop backgrounds and inactive-window vibrancy. Floating controls use a lighter translucent tint with actual backdrop blur; do not reuse their material across every large panel. Text and controls stay opaque and readable.

Light and dark root selectors set these tokens. The normal palette uses platform Messages blues (`#007aff` light, `#0a84ff` dark); `prefers-contrast: more` switches to the darker `--ep-messages-blue-high-contrast` so white bubble text reaches 4.5:1. Discord's noncritical surface, text, control, and input tokens map to these theme tokens. Leave status, error, connected, and disabled tokens alone. Don't use translucency or blur as the only state cue.

## Native macOS vibrancy

The CSS leaves `html`, `body` and the app backing transparent and layers translucent chat, sidebar and floating surfaces above them. For the native frosted material across the full Discord window, open **Discord Settings → Vencord → Vencord → MacOS Window vibrancy style** and select **Sidebar**. Leave **Enable window transparency** off: the Sidebar vibrancy style supplies a transparent window backing without changing Discord's resizing behavior. Fully quit and reopen Discord to apply the native setting. Native vibrancy blurs content behind the window; CSS `backdrop-filter` blurs content behind the floating controls inside Discord. Gradients do not simulate the glass material. Reduce Transparency uses solid surfaces instead.

## Selector map

- **App surfaces:** `#app-mount` backdrop; Discord class stems for channel/chat, sidebars, member list, user panels, composer, popouts, and menus. Float the chat heading capsules over the conversation with top clearance for the message list. Style only direct `toolbar_` children matching clickable `iconWrapper_` role-buttons; preserve disabled icons, the search field, native actions and layout responsiveness. Use class stems such as `[class*="sidebarList_"]`, not build hashes. Keep chat-content transparent rather than stacking its tint on the chat wrapper. Search listboxes use the floating material; the actual chat-header search field needs its own backdrop blur, with matching solid accessibility fallbacks. Sidebar search and labels use the smaller system text rhythm. The current sidebar search is a direct native `button` under `privateChannels_ > searchBar_`; keep `searchBarComponent_` as a legacy fallback, not the only selector. In one-to-one DMs, mention emphasis stays on the message bubble instead of a full-width band; server mention styling is preserved.
- **Settings modal:** scope to the current structural signature: dialog → `outerContainer_` → `container_` + `modal_` → `modalContent_` → `modalContentInner_` → `container_` → adjacent `sidebar__` and `content_`. The sidebar uses `fixedContent__`, `nav__`, `navScroller__`; main header uses `contentHeader_`. This reaches both current Vencord and standard settings pages. Keep the legacy selectors as fallbacks and avoid styling unrelated dialogs.
- **Message bubbles:** only regular rows under `[data-list-id="chat-messages"]`, excluding `.systemMessage_`, targeting the direct `contents_` → `[id^="message-content-"]` child when it either has `.markup_` itself or contains `.markup_`. This covers Discord's current plain-text node. Keep the row, avatar, attachment, embed, reaction, code, and accessibility structure intact. Draw tails with pointer-inert pseudo elements.
- **Replies and reactions:** style the `repliedMessage_` quote as an outlined bubble with a shaped lower corner; draw a short downward curve on the native `repliedMessageClickableSpine_` (mirrored for your own replies) so its expanded hit target is preserved. The quote reserves14pixels below for that connector. Keep `repliedTextPreview_` at its intrinsic flex basis so one-to-one quotes size correctly with their redundant identity controls visually clipped. Those controls remain accessible and reappear on keyboard focus; group/server quotes retain them. Text clipping belongs to the native `repliedTextPreview_`/`repliedTextContent_` children. Style `reaction_` as compact rounded chips without hiding emoji or group counts; reactor faces are hidden and `reactionBtn_` shows only while its row is hovered or focused. The quick-reaction menu is a `wrapper_` group of `customItem_` menu items containing `button_` controls; keep their existing actions and keyboard focus. Message hover actions use `buttonsInner_`.
- **Bubble anchors:** each row sets `anchor-scope: --ep-bubble` and its bubble sets `anchor-name: --ep-bubble`, so anything positioned with `position-anchor: --ep-bubble` follows its own row's bubble and never a neighbour's. Hover timestamps align to the bubble's bottom edge using a flex line without the native inline timestamp padding, leaving the top corner for Tapbacks. Keep Discord's native localized timestamp text and accessible date intact.
- **Tapbacks:** under `:root:is([data-ep-direct-message], [data-ep-group-message])`, a text row's `reactions_` becomes one pill on the bubble's top corner (top-right for others, top-left for your own) with20pixels reserved above the bubble. Pointer-inert dots on the bubble provide the thought-tail contour without clipping the scrollable pill. Long reaction lists scroll horizontally, focused buttons scroll into view, and only your selected chips turn blue. The chips stay real buttons. Server channels keep reactions below the message. Nest any self override inside the Tapback block; a separate rule loses on specificity. Snapchat overrides this with wrapping chips in normal flow and keeps native counts.
- **Own media:** `[id^="message-accessories-"]` in your own rows aligns its children to the end, so your photos, files and embeds sit on the right under your bubbles. Embeds (`article[class*="embedFull_"]`) are rounded cards in the bubble colours with the accent kept as a thin edge.
- **Direct-message density:** `:root[data-ep-direct-message]` applies only to one-to-one DMs. Repeated avatars and their decorations are visually clipped, and the now-unused native avatar minimum height is removed. The existing group-start margin separates runs; reaction rows keep their reserved Tapback space. A keyboard-focused avatar regains its native row space. Message metadata appears on hover or keyboard focus without changing row height; never apply this selector to group DMs or server channels. `:root[data-ep-group-message]` marks a selected group DM; in group DMs and servers other people's runs keep a small name label and their time appears on hover.
- **Composer menu:** Plus adds a trigger through Vencord's ChatBarButton API and portals its own button into the native attachment-button slot. The original Discord/plugin controls stay mounted. Only bounded, labeled actions in the current composer's attachment/button areas are grouped; Send, disabled actions and unknown controls retain their native safeguards. Actions check the account, channel and connected composer before invoking the original handler synchronously, including native file-picker activation. Local line icons avoid dependencies on Discord's animated/masked SVG geometry; unknown actions retain their original labels and use a generic apps icon. The compact rows have colored hover/focus accents and a brief opening motion, disabled with Reduce Motion. Grouping is enabled solely by this theme's CSS and a successful `data-ep-composer-ready` binding. Disabling the theme or plugin restores the original controls. There is no new permission, network call or message-content access.
- **Per-DM wallpaper:** `:root[data-ep-dm-wallpaper]` is distinct from the direct-message marker and is set only for a selected 1:1 or group DM with a saved background. Use the prevalidated `--ep-dm-wallpaper` value only on the chat-content backdrop pseudo layer; don't apply it to servers or the message list itself.
- **Presence+ panel:** `.ep-plus-*` rules may refine the panel while this theme is selected. Don't let the standalone theme change the panel's data, actions, or ownership of local background settings.

Class stems and structural relationships are compatibility hooks, not a public Discord API. Recheck them after Discord updates rather than copying generated suffixes into a new theme. Keep a new theme's palette separate from its component rules so the same surface map can guide another design.

## Update workflow

Before changing selectors after a Discord update, inspect the live element hierarchy and computed styles, record stable class stems and parent relationships, then scope selectors to those relationships. Keep selectors free of generated suffixes. Check the current Vencord modal as well as a legacy Settings layout, regular and system messages, attachment-only rows, one-to-one and group DMs, reactions, reply references, menus, light/dark mode, Reduce Transparency, and forced colors. Verify that each DM marker clears when its chat or account changes and that disabling the standalone theme restores normal Discord styling.
